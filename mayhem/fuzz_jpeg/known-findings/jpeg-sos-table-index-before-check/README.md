# jpeg/jdhuff.c:1445 SOS table number used to form a slot address before it is range-checked

Reproducer: `crash-ed81de9a839438ba89540d9414bca20db5ca7c48` (559 bytes; replay: `/mayhem/fuzz_jpeg-standalone <file>`). Mayhem defect #3609409, `fuzz-jpeg` run 5.

- **Cause:** `get_sos` (`jdmarker.c:380-381`) stores the SOS table selectors as raw nibbles, `dc_tbl_no = (c >> 4) & 15` and `ac_tbl_no = c & 15`, with no range check. In `start_pass_huff_decoder` the baseline path then forms `&entropy->dc_derived_tbls[tbl]` (`jdhuff.c:1445`) and `&entropy->ac_derived_tbls[tbl]` (`:1449`), and the progressive path `&entropy->derived_tbls[tbl]` (`:1402`, `:1407`), before the callee checks the number. The reproducer's third scan component selects tables `0xff`, so `tbl` is 15 and UBSan reports `index 15 out of bounds for type 'd_derived_tbl *[4]'`. The harness is a plain `Fl_JPEG_Image` call; the stack is `jpeg_start_decompress` → `jinit_master_decompress` → `master_selection` → `start_input_pass` → `start_pass_huff_decoder`. Mayhem labels the site `:1445`, the DC call (its continuation line); the AC and progressive calls have the same defect. This is a different root cause from `jpeg-dht-index-before-check` (`get_dht`, `jdmarker.c:506/508`): that one is the DHT table index, this one the SOS table selector.
- **Impact:** low. Only the slot address is computed out of range; it is never dereferenced. The address is passed as `pdtbl` to `jpeg_make_d_derived_tbl`, whose first statement is `if (tblno < 0 || tblno >= NUM_HUFF_TBLS) ERREXIT1(...)`, ahead of every `*pdtbl` read or write. `ERREXIT1` does not return: `Fl_JPEG_Image` installs `fl_jpeg_error_handler`, which `longjmp`s out (`src/Fl_JPEG_Image.cxx:74`). The later `dc_derived_tbls[compptr->dc_tbl_no]` reads (`:741`, `:1460`) only run after that loop has validated every component's number. So this is UB in form, not an observed memory error; it aborts under halting UBSan.
- **Fix:** reject `dc_tbl_no`/`ac_tbl_no` `>= NUM_HUFF_TBLS` in `get_sos` (or before the address is formed in `start_pass_huff_decoder`).
